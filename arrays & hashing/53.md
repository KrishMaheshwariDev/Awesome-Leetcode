# 53. Maximum Subarray

[LeetCode Problem](https://leetcode.com/problems/maximum-subarray/description/)

## Problem Understanding

When I first read the problem and its examples, the first question I asked myself was: **What exactly is a subarray?**

A subarray is a **contiguous, non-empty sequence of elements** from the original array.

The word _contiguous_ is important here. We cannot rearrange the elements, skip elements, or sort the array and choose the largest values. The original sequence must be preserved.

For example, given:

```text
[-2, 1, -3, 4, -1, 2, 1, -5, 4]
```

The maximum-sum subarray is:

```text
[4, -1, 2, 1]
```

with a sum of:

```text
6
```

The goal is therefore to find the contiguous subarray with the largest possible sum.

---

## Brute Force Approach

My first approach was to generate every possible subarray and calculate its sum.

The basic idea was:

1. Start from every index.
2. Extend the subarray one element at a time.
3. Keep track of the current sum.
4. Compare it with the maximum sum found so far.

There is an important small optimization here. Instead of creating an actual subarray and calculating its sum from scratch every time, we can maintain a running sum.

For example:

```text
[4, -1, 2, 1]

Start at 4:
4
4 + (-1) = 3
3 + 2 = 5
5 + 1 = 6
```

So we can enumerate all possible starting points while calculating each possible ending point incrementally.

### Implementation

```cpp
class Solution {
public:
    int maxSubArray(vector<int>& nums) {
        int sum = INT_MIN;

        for (int i = 0; i < nums.size(); i++) {
            int current = 0;

            for (int j = i; j < nums.size(); j++) {
                current += nums[j];
                sum = max(current, sum);
            }
        }

        return sum;
    }
};
```

### Complexity

There are two nested loops. For every starting index, we potentially traverse the remaining elements.

- **Time:** `O(n²)`
- **Space:** `O(1)`

### Verdict

The logic is correct, but the solution resulted in **Time Limit Exceeded** on LeetCode.

So the next question was:

> Can this problem be solved in a single pass?

---

## Searching for an O(n) Approach

My first thought was to use a **variable-size sliding window**.

However, I couldn't find a reliable rule for deciding:

- When should the window expand?
- When should it shrink?
- What condition tells us that the current window is no longer useful?

Unlike problems where a window has a clear constraint, maximum subarray does not provide an obvious condition for moving the left or right boundary.

So I dropped the sliding-window idea.

After looking for a hint, I came across **Kadane's Algorithm**.

The key insight behind Kadane's Algorithm is surprisingly simple:

> If the sum of the subarray we have built so far becomes a disadvantage, there is no reason to carry that negative sum into the next subarray.

---

## Optimized Approach: Kadane's Algorithm

While traversing the array, we maintain two values:

### `maxEndsHere`

The maximum sum of a subarray **ending at the current index**.

At every element, we have two choices:

1. Extend the previous subarray.
2. Start a new subarray from the current element.

Therefore:

```text
maxEndsHere = max(nums[i], maxEndsHere + nums[i])
```

For example, suppose our current sum is:

```text
-5
```

and the next element is:

```text
4
```

We have two possibilities:

```text
-5 + 4 = -1
```

or simply:

```text
4
```

Obviously, starting fresh is better.

This gives us the core idea:

> If the previous accumulated sum hurts the current element, discard it and start a new subarray.

### `maxSoFar`

While `maxEndsHere` tells us the best subarray **ending at the current position**, `maxSoFar` stores the best answer we have encountered anywhere in the array.

After calculating `maxEndsHere`, we update:

```text
maxSoFar = max(maxSoFar, maxEndsHere)
```

This lets us solve the entire problem in one traversal.

---

## Implementation

```cpp
class Solution {
public:
    int maxSubArray(vector<int>& nums) {
        int maxEndsHere = 0;
        int maxSoFar = INT_MIN;

        for (int i = 0; i < nums.size(); i++) {
            maxEndsHere = max(nums[i], maxEndsHere + nums[i]);
            maxSoFar = max(maxEndsHere, maxSoFar);
        }

        return maxSoFar;
    }
};
```

## Complexity

We traverse the array exactly once and use only two variables.

- **Time:** `O(n)`
- **Space:** `O(1)`

---

## Why Does Kadane's Algorithm Work?

The important observation is that a negative running sum can never improve a future subarray.

Suppose we have:

```text
[4, -6, 5]
```

After processing the first two elements:

```text
4 + (-6) = -2
```

Now consider the next element:

```text
5
```

We could continue the previous subarray:

```text
-2 + 5 = 3
```

or start a new subarray:

```text
5
```

Starting again gives us the better result.

The previous `-2` only made the new subarray worse.

This is why Kadane's Algorithm can discard the previous accumulated sum when continuing it is worse than starting from the current element.

The algorithm therefore reduces the problem from:

```text
Generate every possible subarray
        ↓
Calculate their sums
        ↓
Find the maximum
```

to:

```text
Traverse once
    ↓
Decide: extend or restart?
    ↓
Keep the best answer
```

---

## Edge Case: All Negative Numbers

One subtle part of this problem is that the subarray must be **non-empty**.

Consider:

```text
[-5, -2, -8]
```

The answer is:

```text
-2
```

We cannot return `0`, because that would represent an empty subarray.

This is why `maxSoFar` is initialized to `INT_MIN` rather than `0`.

The expression:

```cpp
maxEndsHere = max(nums[i], maxEndsHere + nums[i]);
```

also allows the algorithm to start a new subarray directly from the current element, which handles arrays containing only negative values correctly.

---

## Takeaway

The main lesson from this problem is **Kadane's Algorithm**.

The pattern to remember is:

```text
Best subarray ending here
=
max(
    current element,
    previous best ending here + current element
)
```

The key question is not:

> "How do I generate every possible subarray?"

Instead, ask:

> **"Does carrying the previous subarray into the current position actually help me?"**

If it does, extend it.

If it doesn't, start fresh.

That single observation turns the brute-force `O(n²)` solution into an `O(n)` solution using `O(1)` extra space.

**Pattern:** Dynamic Programming / Kadane's Algorithm  
**Time:** `O(n)`  
**Space:** `O(1)`  
**Final Verdict:** Solved ✅
