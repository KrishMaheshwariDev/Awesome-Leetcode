# 75. Sort Colors

[LeetCode Problem](https://leetcode.com/problems/sort-colors/description/)

## 🧩 Problem Understanding

At first glance, this problem looks more complicated than it actually is.

The problem talks about **red, white, and blue**, but that is essentially a case study around a very simple problem:

> **Sort an array containing only three possible values: `0`, `1`, and `2`.**

For example:

```text
Input:
[2, 0, 2, 1, 1, 0]

Output:
[0, 0, 1, 1, 2, 2]
```

The important detail is that there are only **three distinct values**.

That immediately raises a question:

> 🤔 If the input can contain only `0`, `1`, and `2`, do we really need a general-purpose sorting algorithm?

Before getting there, I started with the most straightforward approach.

---

# 🔨 Brute Force: Bubble Sort

My first thought was simple:

**Just sort the array.**

I used Bubble Sort, with one small optimization.

Normally, Bubble Sort keeps running even if the array becomes sorted before all iterations are completed.

We can avoid those unnecessary iterations by maintaining a `swapped` flag.

### 💡 The Optimization

During each pass:

- If at least one swap happens, the array may still need sorting.
- If **no swap happens**, then the array is already sorted.
- Therefore, we can immediately stop.

The flow looks like this:

```text
             Start
               │
               ▼
       Begin Bubble Sort
               │
               ▼
      Compare adjacent values
               │
        ┌──────┴──────┐
        │             │
     Out of order   In order
        │             │
        ▼             ▼
      Swap          Continue
        │
        ▼
   swapped = true
        │
        └──────┬──────┘
               ▼
          Next pair
               │
               ▼
       End of current pass
               │
               ▼
       Was anything swapped?
          /            \
        No              Yes
        │                │
        ▼                ▼
       STOP         Next pass
```

### Code

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        bool swapped;

        for(int i = 0; i < nums.size() - 1; i++){
            swapped = false;

            for(int j = 0; j < nums.size() - i - 1; j++){
                if(nums[j] > nums[j+1]){
                    swap(nums[j], nums[j+1]);
                    swapped = true;
                }
            }

            if(!swapped){
                break;
            }
        }
    }
};
```

### Complexity

In the worst case, Bubble Sort still requires nested iterations.

- ⏱️ **Time:** `O(n²)`
- 💾 **Space:** `O(1)`

### Verdict

✅ **Accepted**

The solution works, but there is an obvious problem:

We are using a general sorting algorithm for an array that contains only **three possible values**.

That feels wasteful.

---

# 🧠 The Key Observation

The problem gives us a very useful constraint:

```text
nums[i] ∈ {0, 1, 2}
```

There are no other values.

So instead of asking:

> "How do I sort these elements?"

we can ask:

> **"How many `0`s, `1`s, and `2`s are there?"**

Once we know the frequencies, the sorted array is completely determined.

For example:

```text
Input:
[2, 0, 2, 1, 1, 0]

Frequency:

0 → 2
1 → 2
2 → 2
```

Therefore the result must be:

```text
[0, 0, 1, 1, 2, 2]
```

No comparisons are necessary.

No swapping is necessary.

We simply reconstruct the array from the frequencies.

---

# ⚡ Optimized Approach: Counting

The algorithm has two phases.

### Phase 1: Count

Traverse the array once and count:

```text
count0
count1
count2
```

```text
             Input Array
                  │
                  ▼
          ┌───────────────┐
          │ Traverse once │
          └───────┬───────┘
                  │
       ┌──────────┼──────────┐
       ▼          ▼          ▼
    nums[i]=0  nums[i]=1  nums[i]=2
       │          │          │
       ▼          ▼          ▼
   count0++    count1++    count2++
```

### Phase 2: Rewrite

Once the counts are known:

```text
count0 = 2
count1 = 2
count2 = 2
```

we overwrite the original array:

```text
0 0 | 1 1 | 2 2
```

The array is now sorted.

---

# 💻 Implementation

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int count0 = 0;
        int count1 = 0;
        int count2 = 0;

        // Count frequencies
        for(int i = 0; i < nums.size(); i++){
            if(nums[i] == 0){
                count0++;
            }
            else if(nums[i] == 1){
                count1++;
            }
            else{
                count2++;
            }
        }

        // Rewrite the array
        int i = 0;

        while(count0 != 0 || count1 != 0 || count2 != 0){
            if(count0 != 0){
                nums[i] = 0;
                i++;
                count0--;
            }
            else if(count1 != 0){
                nums[i] = 1;
                i++;
                count1--;
            }
            else{
                nums[i] = 2;
                i++;
                count2--;
            }
        }
    }
};
```

# 🔍 Example Walkthrough

Consider:

```text
[2, 0, 2, 1, 1, 0]
```

### Step 1: Count

Traverse the array:

```text
2 → count2 = 1
0 → count0 = 1
2 → count2 = 2
1 → count1 = 1
1 → count1 = 2
0 → count0 = 2
```

Final frequencies:

```text
┌─────────┬───────┐
│ Value   │ Count │
├─────────┼───────┤
│    0    │   2   │
│    1    │   2   │
│    2    │   2   │
└─────────┴───────┘
```

### Step 2: Rewrite

Write two `0`s:

```text
[0, 0, _, _, _, _]
```

Then two `1`s:

```text
[0, 0, 1, 1, _, _]
```

Then two `2`s:

```text
[0, 0, 1, 1, 2, 2]
```

Done. 🎯

---

# 📊 Complexity

The array is traversed once to count the values.

Then we traverse the values again while rewriting the array.

Therefore:

```text
O(n) + O(n)
```

which simplifies to:

- ⏱️ **Time:** `O(n)`
- 💾 **Space:** `O(1)`

The extra space remains constant because we only maintain three counters.

---

# 🆚 Comparing Both Approaches

| Approach                   |    Time |  Space | Result      |
| -------------------------- | ------: | -----: | ----------- |
| Bubble Sort + optimization | `O(n²)` | `O(1)` | ✅ Accepted |
| Counting frequencies       |  `O(n)` | `O(1)` | ✅ Accepted |

The second solution is clearly better for this particular problem.

But there is an important lesson here.

---

# 🧠 Don't Automatically Reach for a Sorting Algorithm

When you see:

> **"Sort this array"**

your first reaction might be:

```text
"Which sorting algorithm should I use?"
```

That is not always the best question.

Instead, inspect the constraints.

Here, the array contains only:

```text
0, 1, 2
```

That changes the problem dramatically.

We don't actually need to determine the relative ordering of arbitrary values. We already know the complete ordering:

```text
0 < 1 < 2
```

All we need is the **frequency of each value**.

```text
        Only 3 possible values
                 │
                 ▼
        Count their frequencies
                 │
                 ▼
       Reconstruct in order
                 │
                 ▼
          Sorted Array
```

This is essentially a **Counting Sort-style idea** specialized to this problem.

---

# 🚀 Could We Go Further?

Yes.

There is an even more famous `O(n)` / `O(1)` solution for this problem: the **Dutch National Flag algorithm**.

It sorts the array in a **single pass** using three pointers:

```text
low     mid             high
 ↓       ↓                ↓
[ 0s ][ unknown values ][ 2s ]
```

The idea is to maintain three regions:

```text
┌─────────┬──────────────┬──────────────┬─────────┐
│   0s    │     1s       │   Unknown    │   2s    │
└─────────┴──────────────┴──────────────┴─────────┘
          ↑              ↑              ↑
         low            mid            high
```

However, my optimized solution above already satisfies the required `O(n)` time and `O(1)` space constraints.

So there is no need to introduce another algorithm just to make the solution look more sophisticated.

The Dutch National Flag approach is worth learning separately because it introduces an important **three-pointer partitioning pattern**, but the counting solution is already a perfectly valid optimization.

---

# 🎯 Takeaway

This problem reinforced an important problem-solving habit:

> **Don't solve the generic version of a problem when the constraints give you a simpler version for free.**

My progression was:

```text
Basic sorting problem
        │
        ▼
Bubble Sort
O(n²), O(1)
        │
        ▼
Look at the constraints
        │
        ▼
Only 3 possible values
        │
        ▼
Count frequencies
        │
        ▼
Reconstruct array
        │
        ▼
O(n), O(1) ✅
```

The biggest insight wasn't a complicated algorithm.

It was recognizing that **the problem's constraints make general sorting unnecessary**.

### 🧠 Pattern to Remember

**Frequency Counting / Counting Sort**

When the number of possible values is small and known, consider:

```text
Count → Reconstruct
```

before reaching for a comparison-based sorting algorithm.

**Brute Force:** Bubble Sort → `O(n²)` / `O(1)` ✅
**Optimized:** Frequency Counting → `O(n)` / `O(1)` ✅
