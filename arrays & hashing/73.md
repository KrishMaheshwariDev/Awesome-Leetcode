# 73. Set Matrix Zeroes

[LeetCode Problem](https://leetcode.com/problems/set-matrix-zeroes/description/)

## 🧩 Problem Understanding

The problem asks us to modify a matrix such that whenever an element is `0`, its **entire row and column become `0`**.

For example:

```text
Input:

1  1  1
1  0  1
1  1  1
```

The `0` is at `(1,1)`, so its entire row and column must become zero:

```text
Output:

1  0  1
0  0  0
1  0  1
```

The tricky part is that we have to do this **in-place**, with a strict constraint on extra space.

That immediately made the problem more interesting.

---

# 🔨 First Approach: Store Every Zero Position

My immediate thought was:

> "First find all the zeros and store their positions. Then use those positions to zero their corresponding rows and columns."

So during the first pass, I store every `(row, column)` position where a zero occurs.

For example:

```text
1  1  1
0  1  1
1  1  0
```

I would store:

```text
(1,0)
(2,2)
```

Then use those positions to modify the matrix.

### Code

```cpp
class Solution {
public:
    void setZeroes(vector<vector<int>>& matrix) {
        vector<vector<int>> zero_pos;

        int row = matrix.size();
        int col = matrix[0].size();

        for(int i = 0; i < row; i++){
            for(int j = 0; j < col; j++){
                if(matrix[i][j] == 0){
                    zero_pos.push_back({i, j});
                }
            }
        }

        if(zero_pos.size() == 0){
            return;
        }

        for(auto i : zero_pos){
            int zero_row = i[0];
            int zero_col = i[1];

            for(int j = 0; j < col; j++){
                matrix[zero_row][j] = 0;
            }

            for(int j = 0; j < row; j++){
                matrix[j][zero_col] = 0;
            }
        }
    }
};
```

The logic itself is correct.

The problem is the **space complexity**.

---

# 📊 Complexity

Let:

- `m` = number of rows
- `n` = number of columns

The first traversal takes:

```text
O(m × n)
```

If every element is zero, we could store up to `m × n` positions.

Therefore:

- ⏱️ **Time:** potentially `O(mn + mn(m+n))`
- 💾 **Space:** `O(mn)`

And the problem does not allow that much extra space.

### Verdict

❌ **Restriction Failed**

The algorithm was logically correct, but it violated the space constraint.

---

# 🧠 First Optimization: We Don't Need Both Coordinates

After seeing the space issue, I thought:

> "Do I really need to store both the row and column for every zero?"

Not necessarily.

If I know that a particular row contains a zero, I can immediately make that row zero.

The only thing I need to remember for later is:

> **Which columns contained zeros?**

That means instead of storing:

```text
(row, col)
(row, col)
(row, col)
```

I can store only:

```text
col
col
col
```

The extra space drops from potentially `O(mn)` to `O(n)`.

That fits the constraint.

---

# ⚡ Second Approach: Zero Rows Immediately, Remember Columns

The idea became:

1. Traverse the matrix.
2. When a zero is found:
   - Find the zero columns in that row.
   - Store those column indices.
   - Make the entire row zero.

3. After finishing the first pass, traverse the stored columns.
4. Make those columns zero.

The basic flow is:

```text
             Scan Matrix
                  │
                  ▼
          Found a zero?
             /       \
           No         Yes
           │           │
           │           ▼
           │     Record columns
           │           │
           │           ▼
           │       Zero row
           │
           └──────► Continue
                       │
                       ▼
                Scan saved columns
                       │
                       ▼
                 Zero columns
```

### Code

```cpp
class Solution {
public:
    void setZeroes(vector<vector<int>>& matrix) {
        vector<int> zero_cols;

        int row = matrix.size();
        int col = matrix[0].size();

        for(int i = 0; i < row; i++){
            for(int j = 0; j < col; j++){
                if(matrix[i][j] == 0){

                    for(int k = 0; k < col; k++){
                        if(matrix[i][k] == 0){
                            zero_cols.push_back(k);
                        }
                    }

                    fill(matrix[i].begin(), matrix[i].end(), 0);
                    break;
                }
            }
        }

        for(auto j : zero_cols){
            for(int i = 0; i < row; i++){
                matrix[i][j] = 0;
            }
        }
    }
};
```

### Complexity

The additional space is now:

- **Space:** `O(n)` in the worst case

The first matrix traversal is `O(mn)`.

However, when a row contains a zero, we scan that row again, and later we scan every stored column.

In the worst case, the implementation can still perform a significant amount of repeated work.

A safe upper-bound characterization is:

- ⏱️ **Time:** `O(mn + mn + mn)` = `O(mn)` for the common bounded-duplicate interpretation, though the vector may contain repeated column indices and the exact implementation can do extra work
- 💾 **Space:** `O(n)`

More importantly, this is still essentially a **brute-force-style solution**.

### Verdict

✅ **Accepted**

But I wasn't satisfied with it.

We reduced the space, but we were still storing information externally that the matrix itself could potentially store.

That led to the hint from LeetCode.

---

# 💡 The Hint: Use the Matrix Itself as Storage

LeetCode's hint suggested something interesting:

> **Use values in the current matrix to flag the rows and columns that need to be zeroed.**

I thought about this for a while.

The problem was:

> How can I store information without using extra memory?

Then the key idea clicked:

## 🧠 Use the First Row and First Column as Flags

Suppose we encounter:

```text
matrix[i][j] == 0
```

That means:

- Row `i` must become zero.
- Column `j` must become zero.

Instead of storing:

```text
row i
column j
```

somewhere else, we can use:

```text
matrix[i][0]
matrix[0][j]
```

as markers.

So:

```text
matrix[i][0] = 0
```

means:

> "Row `i` needs to be zero."

And:

```text
matrix[0][j] = 0
```

means:

> "Column `j` needs to be zero."

This effectively turns part of the matrix into our bookkeeping storage.

```text
                 First Row
       ┌───┬───┬───┬───┬───┐
       │   │ C │ C │   │ C │
       ├───┼───┼───┼───┼───┤
Row R  │ R │   │   │   │   │
       ├───┼───┼───┼───┼───┤
Row R  │ R │   │   │   │   │
       ├───┼───┼───┼───┼───┤
       │   │   │   │   │   │
       └───┴───┴───┴───┴───┘
         ↑
      First Col

R = row marker
C = column marker
```

Now we have effectively achieved:

```text
Extra memory = O(1)
```

But there is one problem.

---

# ⚠️ The First Row and First Column Have a Special Problem

We are using the first row and first column as storage.

But what if they **already contain zeros**?

For example:

```text
0  1  1
1  1  1
1  1  1
```

The zero at `(0,0)` means both:

- First row must be zero.
- First column must be zero.

But once we start using the first row and column as markers, we can no longer distinguish:

> "This zero was originally here"

from:

> "This zero was written here as a marker."

So we need two additional pieces of information.

```text
is_first_row_zero
is_first_col_zero
```

These are just two boolean variables.

Since their number does not grow with the input:

```text
O(1)
```

space.

---

# 🚀 Final Optimized Approach

The algorithm can now be divided into four phases.

```text
┌─────────────────────────────────────┐
│ 1. Check first row and first column │
└──────────────────┬──────────────────┘
                   ▼
┌─────────────────────────────────────┐
│ 2. Use first row/column as markers   │
└──────────────────┬──────────────────┘
                   ▼
┌─────────────────────────────────────┐
│ 3. Zero marked rows and columns      │
└──────────────────┬──────────────────┘
                   ▼
┌─────────────────────────────────────┐
│ 4. Handle first row and first column │
└─────────────────────────────────────┘
```

The order matters.

We first check whether the first row and first column originally contain zero.

Then we can safely use them as markers.

---

# 1️⃣ Check the First Column

We scan the first column:

```cpp
for(int i = 0; i < row; i++){
    if(matrix[i][0] == 0){
        is_first_col_zero = true;
        break;
    }
}
```

If any element is zero, the entire first column will eventually need to become zero.

---

# 2️⃣ Check the First Row

Similarly:

```cpp
for(int j = 0; j < col; j++){
    if(matrix[0][j] == 0){
        is_first_row_zero = true;
        break;
    }
}
```

Now we have preserved the information that would otherwise be destroyed by using the first row and column as markers.

---

# 3️⃣ Mark Rows and Columns

Now we can ignore the first row and first column temporarily.

For every zero:

```cpp
matrix[i][0] = 0;
matrix[0][j] = 0;
```

So the matrix itself records which rows and columns need to be cleared.

```text
Original zero:
        ↓
   matrix[i][j] == 0
        │
   ┌────┴────┐
   ▼         ▼
matrix[i][0] matrix[0][j]
     │           │
     ▼           ▼
 Mark row      Mark column
```

---

# 4️⃣ Zero the Marked Rows

If:

```cpp
matrix[i][0] == 0
```

then row `i` needs to become zero.

We zero everything except the first column for now:

```cpp
for(int i = 1; i < row; i++){
    if(matrix[i][0] == 0){
        for(int j = 1; j < col; j++){
            matrix[i][j] = 0;
        }
    }
}
```

---

# 5️⃣ Zero the Marked Columns

Similarly, if:

```cpp
matrix[0][j] == 0
```

then column `j` needs to become zero.

```cpp
for(int i = 1; i < col; i++){
    if(matrix[0][i] == 0){
        for(int j = 1; j < row; j++){
            matrix[j][i] = 0;
        }
    }
}
```

Notice that we deliberately leave the first row and first column alone for now.

---

# 6️⃣ Handle the First Row and Column

Finally, we use the two boolean flags.

If the first row originally contained a zero:

```cpp
if(is_first_row_zero){
    for(int i = 0; i < col; i++){
        matrix[0][i] = 0;
    }
}
```

If the first column originally contained a zero:

```cpp
if(is_first_col_zero){
    for(int i = 0; i < row; i++){
        matrix[i][0] = 0;
    }
}
```

Now the transformation is complete. 🎯

---

# 💻 Final Code

```cpp
class Solution {
public:
    void setZeroes(vector<vector<int>>& matrix) {
        bool is_first_row_zero = false;
        bool is_first_col_zero = false;

        int row = matrix.size();
        int col = matrix[0].size();

        // Check if first column contains zero
        for(int i = 0; i < row; i++){
            if(matrix[i][0] == 0){
                is_first_col_zero = true;
                break;
            }
        }

        // Check if first row contains zero
        for(int j = 0; j < col; j++){
            if(matrix[0][j] == 0){
                is_first_row_zero = true;
                break;
            }
        }

        // Use first row and first column as markers
        for(int i = 1; i < row; i++){
            for(int j = 1; j < col; j++){
                if(matrix[i][j] == 0){
                    matrix[i][0] = 0;
                    matrix[0][j] = 0;
                }
            }
        }

        // Zero marked rows
        for(int i = 1; i < row; i++){
            if(matrix[i][0] == 0){
                for(int j = 1; j < col; j++){
                    matrix[i][j] = 0;
                }
            }
        }

        // Zero marked columns
        for(int i = 1; i < col; i++){
            if(matrix[0][i] == 0){
                for(int j = 1; j < row; j++){
                    matrix[j][i] = 0;
                }
            }
        }

        // Handle first row
        if(is_first_row_zero){
            for(int i = 0; i < col; i++){
                matrix[0][i] = 0;
            }
        }

        // Handle first column
        if(is_first_col_zero){
            for(int i = 0; i < row; i++){
                matrix[i][0] = 0;
            }
        }
    }
};
```

The zero is at:

(1,1)

So we mark:

The original information has been successfully transformed into **in-place metadata**.

# 🧠 The Real Insight

This problem wasn't really about setting matrix elements to zero.

The deeper problem was:

> **How can I remember which rows and columns need modification without using extra storage?**

The progression makes that clear:

```text
Store (row, col) for every zero
            │
            ▼
        O(mn) space ❌
            │
            ▼
Store only columns
            │
            ▼
          O(n)
            │
            ▼
Use matrix itself as storage
            │
            ▼
          O(1) ✅
```

The first row and first column become a tiny metadata layer embedded directly inside the input.

That's a very useful technique beyond this particular problem.

---

# 📊 Complexity Analysis

Let:

- `m` = number of rows
- `n` = number of columns

We make several passes over the matrix:

1. Check first column → `O(m)`
2. Check first row → `O(n)`
3. Find zeros and mark → `O(mn)`
4. Zero marked rows → `O(mn)`
5. Zero marked columns → `O(mn)`
6. Handle first row → `O(n)`
7. Handle first column → `O(m)`

Therefore:

```text
O(m) + O(n) + O(mn) + O(mn) + O(mn) + O(n) + O(m)
```

which simplifies to:

- ⏱️ **Time:** `O(mn)`
- 💾 **Extra Space:** `O(1)`

This is optimal asymptotically because we have to inspect the matrix elements at least once.

---

# 🆚 Comparing the Approaches

| Approach                    |               Time | Extra Space | Verdict               |
| --------------------------- | -----------------: | ----------: | --------------------- |
| Store every `(row, col)`    | Up to `O(mn(m+n))` |     `O(mn)` | ❌ Restriction failed |
| Store zero columns          |            `O(mn)` |      `O(n)` | ✅ Accepted           |
| First row/column as markers |            `O(mn)` |      `O(1)` | ✅ Optimized          |

The progression is more important than the final code:

```text
Correct logic
     ↓
Space constraint breaks it
     ↓
Reduce stored information
     ↓
Use input as storage
     ↓
O(1) extra space
```

---

# 🎯 Takeaway

This was one of those problems where the **constraint is basically the hint**.

The first solution asked:

> "Where can I store all this information?"

The optimized solution asks:

> **"Why do I need external storage at all?"**

The matrix already contains enough space to encode the information we need.

By reserving the first row and first column as markers, we turn:

```text
Extra memory:
O(m) / O(n)
```

into:

```text
Extra memory:
O(1)
```

without changing the fundamental `O(mn)` time complexity.

### 🧠 Pattern to Remember

**In-Place State Encoding**

When a problem requires `O(1)` auxiliary space, look for ways to use the **input itself as temporary storage**, provided modifying it is allowed.

```text
┌───────────────────────────────┐
│        Input Structure        │
│                               │
│   Data + Metadata together    │
│                               │
└───────────────────────────────┘
```

That idea shows up repeatedly in array and matrix problems.

**Initial:** `O(mn)` extra space ❌
**Second:** `O(n)` extra space ✅
**Final:** `O(mn)` time / `O(1)` extra space ✅
**Final Verdict:** **Solved 🎯**
